# best-skills：让 AI 编程助手拥有专业技能的万能工具箱

在 AI 辅助编程日益普及的今天，我们与 AI 的交互方式正在经历一场静默的变革。过去，你需要在聊天框中反复粘贴精心编写的 Prompt；而现在，一种更优雅的方式正在成为主流——**Agent Skills**。best-skills 正是这一趋势下最具代表性的开源项目之一。

## 项目概览

best-skills（[github.com/xstongxue/best-skills](https://github.com/xstongxue/best-skills)）是一个通用高质量 Agent Skill 合集，由开发者小帅（xstongxue）创建并维护。项目采用 Apache-2.0 开源协议，以 JavaScript 为主要语言，截至目前已收获超过 2000 颗 Star 和 145 次 Fork，是中文社区中最受关注的 Skills 资源库之一。

与传统面向聊天框的 Prompt 合集（如同作者的 best-prompts 项目）不同，best-skills 中的每一条 Skill 都以结构化的 `SKILL.md` 文件形式存在。当你将它安装到 Cursor、Claude Code、Codex 等 AI Agent 工具后，Agent 会根据 `description` 字段中的关键词和你的当前操作场景**自动判断是否调用**，无需每次手动选择或复制粘贴。这意味着你的 AI 助手真正拥有了"条件反射"式的专业能力。

## 项目结构

best-skills 的目录结构清晰简洁，分为三个核心部分：

```
best-skills/
├── LICENSE              # Apache-2.0 开源协议
├── README.md            # 项目说明与使用指南
├── preview/             # 效果预览资源（图片、Draw.io 源文件、PPTX 示例等）
└── skills/              # 核心目录，包含 13 个独立 Skill
    ├── paper-write/          # 学位论文撰写（27 个参考文件）
    ├── patent-write/         # 中文发明专利撰写（11 个参考文件）
    ├── drawio-diagram/       # Draw.io 图表生成（11 个参考文件）
    ├── codegen-diagram/      # 代码生成项目图表（4 个参考文件）
    ├── codegen-doc/          # 代码生成项目文档（4 个参考文件）
    ├── excalidraw-diagram/   # Excalidraw 手绘风图表
    ├── dev-workflow/         # 开发流程五步法（22 个参考文件，含代码审查套件）
    ├── frontend-design/      # 前端高品质界面设计
    ├── wechat-article-writer/# 公众号/自媒体创作（13 个参考文件 + 脚本）
    ├── md-report-summary/    # 周报/汇报/总结/介绍
    ├── pptgen-drawio/        # PPT 生成（4 种风格 + 分析脚本）
    ├── skill-create/         # Skill 创建指南
    └── skill-prompt-convert/ # Skill 与 Prompt 互转
```

项目采用了一种精巧的**路由-加载架构**：每个 Skill 的 `SKILL.md` 文件充当路由器，根据用户输入的关键词自动匹配到 `reference/` 子目录下的具体参考文件执行。这种设计让主文件保持精简（通常 50-250 行），同时将深厚的领域知识分散到按需加载的参考文件中，既节省了 AI 的上下文窗口，又保证了专业深度。

值得一提的是，`wechat-article-writer` 和 `pptgen-drawio` 两个 Skill 还附带了可执行脚本（Python、Node.js、Bash），是项目中仅有的两个跨越纯 Prompt 资产进入可部署软件范畴的 Skill。

## 13 个 Skill 全面解析

### 一、学术论文与专利

#### 1. paper-write —— 本科与硕士学位论文全流程

**功能定位**：覆盖论文撰写全生命周期的统一 Skill，从大纲审核到最终润色，理工科与文科双线支持。

**核心能力**：

- **大纲审核**：自动区分理工科与文科，按不同维度审查大纲的合理性。理工科关注技术闭环和工作量饱满度（本科与硕士标准不同），文科关注理论框架和论证逻辑。
- **结构仿写**：提供"学其神不抄其形"的仿写能力。上传一篇参考范文和你的草稿，Skill 会分析范文的叙事结构和论证方式，然后用你的数据和内容按同样的结构重写。理工科支持绪论、摘要、实验三个章节；文科额外覆盖文献综述、案例分析、对策建议、理论章节。
- **参考文献**：严格遵循 GB/T 7714-2015 国家标准（国内学术论文的硬性要求），支持期刊论文 [J]、会议论文 [C]、学位论文 [D]、专著 [M] 四种类型，绝不编造不存在的文献。
- **润色与去 AI 化**：可能是整个项目中最精细的模块。`anti-aigc.md` 参考文件定义了六大规则块，包括词汇句式去翻译腔（禁用"进行""利用""显著提升"等 AI 高频词）、结构自然化（禁止列表式论述和"首先/其次/综上"式机械连接词）、统计语义重构（打破句子长度均匀性，引入低频词汇，真正重组论述而非表面同义词替换）。
- **其他能力**：扩写/缩写、中英互译、结构化信息提取（为答辩 PPT 准备素材）、格式检查。

**实际场景**：大四学生用"大纲审核"功能确认毕设论文框架合理性，然后用"结构仿写"参照导师推荐的核心期刊论文风格撰写实验章节，最后用"去 AI 化润色"确保通过 AIGC 检测。

**技术细节**：强制 Word 适配输出——严禁 Markdown 格式、中英文与数字之间自动加空格、使用全角中文标点。这解决了将 AI 输出粘贴到 Word 时最常见的格式问题。该 Skill 拥有 27 个参考文件，是项目中引用资源最丰富的 Skill。

#### 2. patent-write —— 中文发明专利全流程

**功能定位**：覆盖中文发明专利撰写全生命周期，从题目优化到最终统稿。

**核心能力**：

- **题目优化与收敛**：帮你将过于宽泛的题目收窄到合适的保护范围。
- **权利要求书**：独立权利要求与从属权利要求的层级构建，这是专利的法律核心。
- **附图绘制**：使用 Draw.io 生成符合专利局要求的黑白中文附图。
- **统稿自检**：术语一致性检查，确保全文用词统一。
- **参考专利蒸馏**：分析已有专利的写法套路，提炼可复用的结构模式。

**默认写作顺序**：提炼创新点 → 权利要求骨架 → 摘要与发明内容 → 具体实施方式 → 统稿。这个顺序并非随意——它遵循"先法律后技术"的专利撰写最佳实践，先确立保护范围再展开技术描述。

**实际场景**：研发工程师完成技术创新后，提供技术方案草稿，使用 patent-write 逐步生成完整的发明专利申请文件。先用"题目收敛"确定保护范围，再用"权利要求"建立法律保护层级，然后用"附图绘制"生成规范的专利附图。

#### 3. codegen-doc —— 代码生成项目文档

**功能定位**：基于当前项目代码自动生成各类文档，支持四种输出类型。

**核心能力**：

- **论文章节生成**：读取项目代码和 README，自动生成系统总体设计、详细设计等论文章节。
- **项目梳理**：按"概述-模块-技术栈"结构整理项目全貌。
- **重点问题分析**：提炼项目的技术难点和待解决问题。
- **简历项目描述**：将当前项目格式化为简历中可直接使用的项目经历。

**核心原则**：绝不编造——仓库中没有的信息不写，所有描述都从代码、注释和 README 中提取，有据可依。

**实际场景**：毕业季学生用"论文章节生成"为毕设论文撰写系统设计章节；求职者用"简历项目描述"把实习项目转化为简历亮点。

#### 4. pptgen-drawio —— 论文答辩与汇报 PPT 生成

**功能定位**：根据论文或汇报内容生成多页 Draw.io 格式 PPT，并自动导出为 .pptx 文件。

**核心能力**：

- **论文答辩模式**：默认 23 页标准答辩结构（封面 → 目录 → 6 个章节标题+内容页 → 已有成果 → 致谢/Q&A）。
- **通用汇报模式**：灵活的汇报结构（封面 → 目录 → 节标题 → 内容 → 总结 → 致谢 → Q&A）。
- **5 种视觉风格**：经典学术（深蓝+金铜，庄重严谨）、现代极简（近黑+亮黄，大字报风格）、暖色学术（蓝灰+砖红，亲和力强）、科技明快（科技蓝，现代前沿感）、自定义（从用户提供的 .pptx 模板提取风格）。
- **自定义模板提取**：通过内置的 `analyze_pptx.py` 脚本分析现有 PPT 模板，自动提取配色、字号、布局等信息生成自定义风格文件。

**技术亮点**：内置 10 条致命检查项——多页 XML 结构校验、id 唯一性、正文换行符规范（禁止使用 `&#xa;` 等实体字符，否则导出时会显示乱码）、遮挡检查、高度预算计算等。这些都是实际使用中反复踩坑后沉淀的经验。

**实际场景**：答辩季学生用"论文答辩模式+经典学术风格"一键生成答辩 PPT 的 Draw.io 文件，然后用 `drawio2pptx` 命令导出为 PowerPoint 格式。企业员工用"通用汇报模式"快速制作季度汇报幻灯片。

### 二、图表绘制

#### 5. drawio-diagram —— Draw.io 图表（从零生成 + 风格迁移）

**功能定位**：生成标准 Draw.io (.drawio) 格式的可视化图表，支持从零生成和风格迁移两种模式。

**核心能力**：

- **风格迁移**：上传一张参考图并描述新内容，Skill 会按参考图的配色、排版和视觉风格生成新图。这是最具创意的功能——你可以拿一张顶会论文中的精美架构图，让它用同样的风格画出你自己模型的架构图。
- **深度学习模型架构图**：CNN、Transformer、RNN、GAN 等经典架构的标准化绘制，使用 3D 立方体（`shape=cube`）表示网络层，虚线表示残差连接。
- **考试示意图**：覆盖数学（函数图像、几何图形）、物理（受力分析、电路图）、化学（原子结构）、生物（细胞结构）、地理（地球圈层）、历史（朝代时间轴）、语文（古诗分析）七大学科。
- **UML 图**：时序图、类图、状态图的标准绘制。

**技术约束**：严格遵循 Draw.io XML 规范——标签闭合、`vertex="1"`/`edge="1"` 属性、唯一 id、特殊字符转义。输出附带使用说明（打开方式、PNG/SVG/PDF 导出、论文图题引用格式）。

**实际场景**：研究生用风格迁移功能复刻 CVPR 论文中的模型架构图为自己的论文配图；中学教师用考试示意图功能快速制作物理受力分析图用于教学。

#### 6. codegen-diagram —— 代码生成项目图表

**功能定位**：读取当前项目代码，自动生成四种类型的 Draw.io 技术图表。

**核心能力**：

- **技术栈图**：前端/后端/模型服务三大模块的技术栈组成与通信方式。
- **系统架构图**：标准四层架构（表现层/接口层/业务层/持久层），使用圆柱体表示数据库。
- **数据结构图**：ER 风格的表结构可视化，展示字段名、类型和约束。
- **E-R 图**：严格的 Chen 记号法——矩形表示实体、菱形表示联系、椭圆表示属性、主键下划线标注。

**统一学术配色**：白底 `#FFFFFF`、主色 `#3366CC`、副色 `#7FBFFF`、强调 `#FF9966`，Helvetica 字体 11-13pt。四张图使用统一配色，确保多图表论文中视觉风格一致。

**实际场景**：毕设论文中需要系统架构图和 E-R 图时，直接用 codegen-diagram 读取项目代码生成，确保图表与实际系统完全一致。

#### 7. excalidraw-diagram —— Excalidraw 手绘风图表

**功能定位**：生成可在 Excalidraw 中打开的手绘风 `.excalidraw` 图表，适合非正式场景。

**核心能力**：

- **系统架构图**：手绘风格的三层架构图。
- **业务流程图**：近似时序图的业务流程展示。
- **模块依赖图**：项目模块间的依赖关系可视化。
- **自由白板草图**：任意结构的白板涂鸦。

**设计理念**：手绘风格的非正式感让它特别适合与非技术同事沟通、快速头脑风暴、以及在 Slack/Discord 中分享轻量级技术说明。输出标准 Excalidraw JSON 格式，可直接在 Excalidraw 编辑器中二次编辑。

**实际场景**：在团队周会上用手绘风架构图快速说明一个技术方案的设计思路；给产品经理画一张手绘流程图解释业务流程。

### 三、软件开发

#### 8. dev-workflow —— 开发流程五步法

**功能定位**：覆盖软件开发全生命周期的结构化工作流，从需求到修复一气呵成。

**核心能力**：

- **需求理解**：五步子流程——信息收集（核心目标/使用场景/输入输出/约束/参考五个维度）→ 需求拆解（P0/P1/P2 优先级分级、功能与非功能需求分离）→ 验收标准（Given-When-Then 格式）→ 输出标准文档 → 确认并自动落盘。
- **方案设计**：从需求文档出发的技术方案设计，包含架构选型、接口设计和数据模型。
- **代码实现**：按模块逐步实现，每文件独立输出，带编码/组织/错误处理三层关键模式。实现前必须与用户确认实现清单。
- **代码审查**：这是 dev-workflow 最厚重的模块，内含 22 个参考文件的 review-kit 审查套件，覆盖 C、C++、Go、Java、Python、Rust、TypeScript、React、Vue、Qt、CSS 十一种语言/框架的专项审查指南，外加架构审查（SOLID 原则检测、反模式识别、耦合内聚量化评估）、性能审查、安全审查（OWASP 标准，每条规则带可运行的反面示例）三个通用指南。
- **Bug 修复**：四步自动修复流程——复现/定位 → 列出优先级排序的修复方案表 → 自动依次尝试（失败则回滚）→ 报告根因与采纳方案。排序原则：零副作用微调 → 局部逻辑 → 架构/依赖 → 大规模重构。

**自动落盘机制**：需求理解、方案设计、代码审查三个阶段会自动将输出写入项目的 `docs/` 目录（单模块写入 `docs/<阶段>.md`，多模块写入 `docs/<模块>/<阶段>.md`），文件不存在则创建、存在则追加，带时间标题和分隔线。这把瞬时的聊天对话转化为了持久的项目文档。

**实际场景**：独立开发者从"我想做一个 XXX"开始，依次经历需求理解 → 方案设计 → 代码实现 → 代码审查，整个开发过程的文档自动沉淀到 `docs/` 目录。团队成员提交 PR 后，用代码审查功能按团队规范进行 Review。

#### 9. frontend-design —— 前端高品质界面设计

**功能定位**：生成具有高设计品质、可交付生产的前端界面代码，刻意规避"AI 通用审美"。

**核心能力**：

- **设计思维四问**：动手前先回答目的、调性、约束、差异化四个问题，确定鲜明的美学方向。
- **11 种参考风格**：极简克制、繁复张扬、复古未来、有机自然、奢华精致、玩具感、编辑/杂志、粗野原始、装饰艺术、马卡龙柔和、工业机械——每种风格都有明确的字体、配色和布局指引。
- **美学维度控制**：字体（禁用 Arial/Inter/思源黑体的默认感）、色彩（CSS 变量管理，WCAG AA 对比度 ≥ 4.5:1）、动效（CSS 优先，`prefers-reduced-motion` 兼容）、版式（非常规布局、不对称、留白比预想多 30%）、背景（渐变网格、噪点纹理、几何图案）。
- **明确的禁忌清单**：Inter/Roboto/Arial 堆砌、白底紫蓝渐变（AI 生成的万恶之源）、模板化居中布局、反复收敛到 Space Grotesk 等同一套组合。

**设计理念**：这个 Skill 的价值不在于"如何生成代码"，而在于"什么是丑陋的"——它用详尽的禁忌清单和鲜明的风格指引，对抗 AI 生成代码中最常见的审美趋同问题。

**实际场景**：产品经理需要一个有记忆点的产品落地页，指定"编辑/杂志风"；开发者需要一个科技感仪表盘，指定"科技明快"风格，获得有创意的、不像 AI 生成的界面代码。

### 四、内容创作与汇报

#### 10. wechat-article-writer —— 公众号/自媒体全流程

**功能定位**：从选题到发布的全链路自媒体创作工具，是整个项目中工程化程度最高的 Skill。

**核心能力**：

- **9 种写作风格**：默认随笔（2000-4000 字）、高流量爆款、清单体/方法论、资源盘点、个人实测、认知颠覆、身份共鸣/逆袭、故事化情感、深度随笔（4000-7000 字）。每种风格有独立的参考文件定义人设、语言特征和结构模板。
- **多源素材搜索**：并行搜索官方文档、Twitter/X、Reddit、技术论坛，优先获取当月当季的最新信息。
- **封面与插图生成**：使用 Draw.io 生成公众号封面（1283×383 合并封面，含大封面+小封面）和正文插图，保存到 `images/` 目录，可通过 `export-drawio.sh` 脚本批量导出 PNG。
- **风格提取**：分析一篇已有公众号文章的写作风格，输出可复用的风格规则包（100-200 字画像 + 15-30 条规则 + 复刻 Prompt + 自检清单）。
- **草稿上传**：支持手动上传（通过 Doocs MD 编辑器）和自动上传（通过 `upload-to-wechat.js` 脚本调用微信公众号 API，需配置 `.env` 中的 `WECHAT_APPID` 和 `WECHAT_SECRET`）。

**工程化特征**：这是唯一一个附带 `package.json`、`.env.example`、README 和可执行脚本的 Skill，本质上是一个可部署的 npm 应用。

**实际场景**：技术博主用"高流量风格"撰写一篇关于 AI 工具的公众号文章，自动搜索最新资料，生成 5 个爆款标题，配上封面图和步骤插图，最后通过 API 直接上传为公众号草稿。

#### 11. md-report-summary —— Markdown 周报/汇报/总结/介绍

**功能定位**：生成高质量 Markdown 格式的职场文档。

**核心能力**：

- **四条分支路径**：周报（表格化本周完成/进行中/下周计划）、工作汇报（结论前置+状态标记）、总结/复盘（量化成果+可执行改进）、介绍（核心能力+适用场景）。
- **智能素材获取**：无草稿时自动进行 Web 搜索并总结（仅参考不照抄）；有草稿时结合草稿整理、润色、补充。
- **质量标准**：有结论而非陈述（"做了什么 → 结果如何"）、数据必须具体、问题描述三要素（现象/根因/影响范围）、计划可执行不写"继续推进"类空话。

**核心原则**：不省略、不编造、图片路径原样保留、格式统一不滥用加粗。

**实际场景**：周五下午快速生成周报——告诉 AI 本周做了哪些事，它会自动整理成结构化表格并补充行业背景信息；季度末用"工作汇报"功能生成带状态标记和量化成果的汇报材料。

### 五、工具与元技能

#### 12. skill-create —— Skill 创建指南

**功能定位**：元技能——教你如何创建新的 Agent Skill。

**核心能力**：

- **需求收集六步法**：purpose/scope、target location、trigger、domain knowledge、output format、existing patterns。
- **SKILL.md 规范指南**：YAML 元数据（name 最长 64 字符小写短横线，description 最长 1024 字符）、第三人称描述、WHAT + WHEN 结构。
- **创作最佳实践**：简洁优先（每个 token 都在与对话历史竞争）、SKILL.md 控制在 500 行以下、渐进式披露（核心放主文件，详细放 reference，引用只一层深）、自由度与任务匹配。
- **反模式警告**：Windows 风格路径、选项过多、时间敏感信息、术语不一致、模糊技能名（避免 `helper`/`utils`/`tools`）。

**实际场景**：当你发现自己在某个领域反复向 AI 解释同样的上下文和规则时，用 skill-create 把这些知识封装为一个 Skill，一劳永逸。

#### 13. skill-prompt-convert —— Skill 与 Prompt 互转

**功能定位**：在结构化 SKILL.md 与聊天框 Prompt 之间双向转换的桥梁工具。

**核心能力**：

- **Skill → Prompt**：将 SKILL.md 转换为可在任何聊天框中使用的标准 Prompt（`# Role` + `# Task` + `# Workflow` + `# Output Format` 格式）。
- **Prompt → Skill**：将一段聊天 Prompt 提炼为结构化的 SKILL.md 文件，自动生成 YAML 元数据。

**实际场景**：你有一个反复使用的长 Prompt，想把它升级为可自动触发的 Skill——用 skill-prompt-convert 一键转换。或者你创建了一个 Skill 但偶尔需要在不支持 Skills 的工具中使用，转换为 Prompt 即可。

## 在主流 AI 工具中安装与使用

best-skills 的最大优势之一是其广泛的兼容性。以下是在各主流 AI Agent 工具中的完整操作方法。

### Cursor

Cursor 是目前最流行的 AI 编程 IDE，原生支持 Skills 功能。

**安装**：将 `skills/` 目录下的目标 Skill 文件夹复制到 Cursor 的 Skills 目录。支持两个层级：个人级（所有项目共享）放置在 `~/.cursor/skills/` 下；项目级（仅当前项目）放置在项目根目录的 `.cursor/skills/` 下。

```bash
# 安装到个人目录（所有项目共享）
cp -r skills/drawio-diagram ~/.cursor/skills/
cp -r skills/paper-write ~/.cursor/skills/

# 安装到项目目录（仅当前项目）
cp -r skills/dev-workflow .cursor/skills/
```

**使用**：安装后无需手动激活。在 Cursor 的 Chat 或 Composer 中正常输入指令，Agent 会根据 Skill 的 description 字段自动匹配并调用。例如输入"帮我画一个 CNN 架构图"，Agent 会自动调用 drawio-diagram Skill。

**更新**：删除旧版本文件夹，复制新版本文件夹即可。

```bash
rm -rf ~/.cursor/skills/drawio-diagram
cp -r skills/drawio-diagram ~/.cursor/skills/
```

**卸载**：直接删除对应的 Skill 文件夹。

```bash
rm -rf ~/.cursor/skills/drawio-diagram
```

### Claude Code

Claude Code 是 Anthropic 推出的命令行 AI 编程工具，对 Skills 有完善的原生支持。

**安装**：

```bash
# 个人级
cp -r skills/patent-write ~/.claude/skills/

# 项目级
cp -r skills/patent-write .claude/skills/
```

**使用**：在 Claude Code 的交互式命令行中直接输入自然语言指令，Claude 会自动识别并调用已安装的 Skill。

**更新与卸载**：与 Cursor 相同，替换或删除对应文件夹即可。

### Codex（OpenAI）

Codex 是 OpenAI 的 AI 编程 Agent。

**安装**：

```bash
# 通过环境变量定位
cp -r skills/dev-workflow $CODEX_HOME/skills/

# 或项目级
cp -r skills/dev-workflow .codex/skills/
```

**使用、更新与卸载**：逻辑同上。

### Trae

Trae 是字节跳动推出的 AI IDE。Skills 安装路径和方法请参考 [Trae 官方文档](https://docs.trae.cn/ide/skills)。

### GitHub Copilot

GitHub Copilot 在 VS Code 中支持 Agent Skills。安装路径和方法请参考 [VS Code 官方文档](https://code.visualstudio.com/docs/copilot/customization/agent-skills)。

### OpenSkills

OpenSkills 是一个跨平台的 Skills 管理工具。安装方法请参考 [OpenSkills 仓库](https://github.com/numman-ali/openskills)。

### OpenClaw

OpenClaw 是另一个支持 Agent Skills 的平台。安装方法请参考 [OpenClaw 文档](https://docs.openclaw.ai/zh-CN/tools/skills)。

### 通用快捷操作

无论使用哪个平台，核心操作都是三步：

```bash
# 1. 克隆仓库
git clone https://github.com/xstongxue/best-skills.git

# 2. 复制需要的 Skill 到目标目录（以 Cursor 为例）
cp -r best-skills/skills/<skill-name> ~/.cursor/skills/

# 3. 更新时：拉取最新版本并覆盖
cd best-skills && git pull
cp -r skills/<skill-name> ~/.cursor/skills/
```

## 为什么选择 best-skills

在众多的 Skills 资源库中，best-skills 有几个突出的特质值得特别提及。

首先是**中文场景的深度适配**。论文 Skill 遵循 GB/T 7714 参考文献国标、去 AIGC 检测规则，专利 Skill 贴合中国发明专利格式，公众号 Skill 对接微信发布 API——这些都不是简单翻译英文 Prompt 就能实现的，需要对中文学术和创作生态有深入理解。

其次是**路由式架构设计**。所有 Skill 共享一致的"关键词匹配 → 参考文件加载 → 结构化输出"模式，使得添加新能力只需增加一个参考文件，而无需修改主文件。这种设计也让每个 Skill 的主文件保持精简，不浪费 AI 的上下文窗口。

第三是**实战经验的沉淀**。pptgen-drawio 中反复强调的"禁止 `&#xa;` 实体字符"、paper-write 中强制的"中英文空格"和"全角标点"、dev-workflow 中的自动落盘机制——这些都是大量实际使用后反复踩坑、修正、优化的结果，而非纸上谈兵的设计。
